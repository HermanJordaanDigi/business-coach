# Data Dictionary

## Overview

This data dictionary provides comprehensive documentation for all data fields in the Business Coaching Analytics project. It includes field definitions, data types, valid values, business rules, and usage examples.

## Quick Reference

| Field | Type | Source | Key | Description |
|-------|------|--------|-----|-------------|
| id | Integer | Database | PK | Unique sale identifier |
| date | Date | Sales System | - | Transaction date |
| name | String | CRM | - | Customer name |
| email | String | CRM | - | Customer email |
| revenue | Decimal | Sales System | - | Total sale amount |
| cash_collected | Decimal | Accounting | - | Cash received |
| product | String | Sales System | FK | Product purchased |
| closer | String | HR System | FK | Sales closer name |
| country | String | CRM | - | Customer country |
| upsell | Boolean | Sales System | - | Upsell flag |
| created_at | Timestamp | Database | - | Record creation time |

## Detailed Field Definitions

### id

**Description**: Unique identifier for each sales transaction

**Technical Details**:
- **Data Type**: INTEGER (SERIAL)
- **Size**: 4 bytes
- **Range**: 1 to 2,147,483,647
- **Nullable**: No
- **Primary Key**: Yes
- **Auto-increment**: Yes

**Business Rules**:
- Automatically generated by database
- Unique across all sales records
- Never reused, even if record is deleted
- Used for foreign key relationships (if applicable)

**Usage**:
```python
# Retrieve sale by ID
sale = get_sale_by_id(123)

# Reference in API
GET /api/sales/123
```

**Sample Values**:
```
1, 2, 3, 4, 5, ..., 195
```

### date

**Description**: Date when the sale transaction occurred

**Technical Details**:
- **Data Type**: DATE
- **Format**: YYYY-MM-DD
- **Size**: 4 bytes
- **Nullable**: No
- **Indexed**: Yes (idx_sales_date)

**Business Rules**:
- Must be a valid calendar date
- Range: 2025-01-01 to 2025-03-31 (current dataset)
- Cannot be in the future
- Used for time-based analysis and reporting
- Affects monthly cohort analysis

**Usage**:
```sql
-- Filter by date range
SELECT * FROM sales WHERE date BETWEEN '2025-01-01' AND '2025-01-31';

-- Monthly aggregation
SELECT DATE_TRUNC('month', date) as month, SUM(revenue)
FROM sales
GROUP BY month;
```

**Sample Values**:
```
2025-01-02
2025-01-15
2025-02-10
2025-03-22
```

**Business Rules**:

- Not guaranteed to be unique (different customers can have same name)

### email

- **Data Type**: VARCHAR(100)
- **Size**: Variable, up to 100 characters
- **Nullable**: No

### revenue

**Description**: Total revenue amount from the sale in USD

**Technical Details**:
- **Data Type**: DECIMAL(10, 2)
- **Precision**: 10 total digits, 2 decimal places
- **Range**: 0.01 to 99,999,999.99
- **Currency**: USD ($)
- **Nullable**: No

**Business Rules**:
- Must be positive (revenue > 0)
- Represents total contract value
- May be paid over time (see cash_collected)
- Used for revenue reporting and forecasting
- Three standard price points:
  - Elite Business Accelerator: $15,000
  - Executive Leadership Mastery: $25,000
  - Scale to 7-Figures Program: $50,000

**Calculations**:
```python
# Total revenue
total = df['revenue'].sum()

# Average deal size
avg_deal = df['revenue'].mean()

# Revenue by product
product_revenue = df.groupby('product')['revenue'].sum()
```

**Sample Values**:
```
15000.00
25000.00
50000.00
```

### cash_collected

**Description**: Actual cash amount collected from the customer in USD

**Technical Details**:
- **Data Type**: DECIMAL(10, 2)
- **Precision**: 10 total digits, 2 decimal places
- **Range**: 0.00 to 99,999,999.99
- **Currency**: USD ($)
- **Nullable**: No

**Business Rules**:
- Must be non-negative (cash_collected >= 0)
- Cannot exceed revenue (cash_collected <= revenue)
- Typically 85-95% of revenue (cash collection rate)
- Represents actual cash in bank
- Difference from revenue represents:
  - Outstanding payments
  - Payment plans
  - Potential bad debt

**Calculations**:
```python
# Cash collection rate
collection_rate = (cash_collected / revenue) * 100

# Outstanding balance
outstanding = revenue - cash_collected

# Total cash collected
total_cash = df['cash_collected'].sum()
```

**Sample Values**:
```
13500.00  (90% of $15,000)
22750.00  (91% of $25,000)
45608.62  (91.2% of $50,000)
```

### country

### upsell

**Description**: Boolean flag indicating whether this sale was an upsell to an existing customer

**Technical Details**:
- **Data Type**: BOOLEAN
- **Size**: 1 byte
- **Values**: TRUE, FALSE (or 1, 0)
- **Nullable**: No
- **Default**: FALSE
- **Indexed**: Yes (idx_sales_upsell)

**Business Rules**:
- TRUE: Sale was an upsell/cross-sell to existing customer
- FALSE: Sale was to a new customer
- Probability varies by product (10-15%)
- Used for conversion rate analysis
- Important for CLV (Customer Lifetime Value) calculations
- Affects marketing attribution

**Calculations**:
```python
# Upsell conversion rate
upsell_rate = (df['upsell'].sum() / len(df)) * 100

# Upsell revenue vs new customer revenue
upsell_revenue = df[df['upsell'] == True]['revenue'].sum()
new_customer_revenue = df[df['upsell'] == False]['revenue'].sum()

# Upsell rate by product
upsell_by_product = df.groupby('product')['upsell'].mean() * 100
```

**Usage**:
```sql
-- Upsell conversion rate
SELECT
    COUNT(CASE WHEN upsell THEN 1 END)::DECIMAL / COUNT(*) * 100 as upsell_rate
FROM sales;

-- Upsells by product
SELECT product, COUNT(*) as upsell_count
FROM sales
WHERE upsell = TRUE
GROUP BY product;
```

**Sample Values**:
```
TRUE
FALSE
```

### created_at

**Description**: Timestamp when the record was created in the database

**Technical Details**:
- **Data Type**: TIMESTAMP
- **Format**: YYYY-MM-DD HH:MM:SS.ffffff
- **Timezone**: UTC
- **Nullable**: Yes
- **Default**: CURRENT_TIMESTAMP (auto-populated)

**Business Rules**:
- Automatically set by database on INSERT
- Immutable (doesn't change on UPDATE)
- Used for audit trail
- Different from sale date (date field is transaction date)
- Useful for data pipeline monitoring
- Helps identify data loading issues

**Usage**:
```sql
-- Recent records
SELECT * FROM sales
WHERE created_at >= NOW() - INTERVAL '1 hour';

-- Data loading audit
SELECT
    DATE_TRUNC('day', created_at) as load_date,
    COUNT(*) as records_loaded
FROM sales
GROUP BY load_date
ORDER BY load_date DESC;
```

**Sample Values**:
```
2025-01-15 14:23:45.123456
2025-01-15 14:23:45.234567
2025-01-15 14:23:45.345678
```

## Calculated Fields

These fields are not stored in the database but are commonly calculated in analysis:

### collection_rate

**Description**: Percentage of revenue that has been collected as cash

**Formula**:
```python
collection_rate = (cash_collected / revenue) * 100
```

**Range**: 0% to 100%
**Typical Values**: 85% to 95%

**Usage**:
```sql
SELECT
    id,
    revenue,
    cash_collected,
    (cash_collected / revenue * 100) as collection_rate
FROM sales;
```

### outstanding_balance

**Description**: Amount of revenue not yet collected

**Formula**:
```python
outstanding_balance = revenue - cash_collected
```

**Range**: $0 to revenue amount

**Usage**:
```sql
SELECT
    SUM(revenue - cash_collected) as total_outstanding
FROM sales;
```

---

### deal_size_category

**Description**: Categorical grouping of deals by revenue size

**Categories**:
- Small: $15,000 (Elite Business Accelerator)
- Medium: $25,000 (Executive Leadership Mastery)
- Large: $50,000 (Scale to 7-Figures Program)

**Usage**:
```python
def categorize_deal(revenue):
    if revenue >= 50000:
        return 'Large'
    elif revenue >= 25000:
        return 'Medium'
    else:
        return 'Small'

df['deal_size_category'] = df['revenue'].apply(categorize_deal)
```

## Data Quality Rules

### Completeness

All fields are required (NOT NULL) except:
- `created_at` (auto-populated)

Expected completeness: 100% for all fields

### Accuracy

- Email addresses must be valid format
- Dates must be within valid range
- Amounts must be positive and realistic
- Country codes must be valid
- Product names must match catalog
- Closer names must be active employees

### Consistency

- `cash_collected <= revenue` (enforced by constraint)
- `date` should not be in the future
- Product prices should match standard pricing
- One closer per sale

### Uniqueness

- `id` is unique (primary key)
- `email` should be unique per customer (business rule)
- Combination of `(date, email, product)` could be unique

## Privacy & Security

### Personally Identifiable Information (PII)

Fields containing PII:
- `name` - Direct identifier
- `email` - Direct identifier

**Handling Requirements**:
- Encrypt in transit (SSL/TLS)
- Encrypt at rest (database encryption)
- Access control (role-based permissions)
- Audit logging for access
- GDPR/CCPA compliance required
- Anonymize for non-production environments

### Sensitive Business Information

Fields containing sensitive business data:
- `revenue` - Financial data
- `cash_collected` - Financial data
- `closer` - Employee information

**Handling Requirements**:
- Restrict access to authorized users
- Audit trail for modifications
- Aggregate before sharing externally

## Usage Guidelines

### For Analysts

```python
# Load data
import pandas as pd
from src.db_utils import get_db_connection

conn = get_db_connection()
df = pd.read_sql("SELECT * FROM sales", conn)

# Basic analysis
print(df.describe())
print(df.groupby('product')['revenue'].sum())

# Calculate metrics
df['collection_rate'] = (df['cash_collected'] / df['revenue']) * 100
df['outstanding'] = df['revenue'] - df['cash_collected']
```

### For API Developers

```python
# Access via API
import requests

# Get sales data
response = requests.get('http://localhost:8000/api/sales', params={
    'page': 1,
    'page_size': 50,
    'product': 'Scale to 7-Figures Program'
})
sales = response.json()['sales']

# Get metrics
response = requests.get('http://localhost:8000/api/metrics/summary')
metrics = response.json()
```

### For SQL Queries

```sql
-- Performance overview
SELECT
    COUNT(*) as total_sales,
    SUM(revenue) as total_revenue,
    AVG(revenue) as avg_deal_size,
    SUM(cash_collected) / SUM(revenue) * 100 as collection_rate,
    COUNT(CASE WHEN upsell THEN 1 END)::DECIMAL / COUNT(*) * 100 as upsell_rate
FROM sales;
```
